# Tiro landing design behavioral rubric

Score observable behavior, not the presence of exact phrases. A response fails if any mandatory item fails.

## Global mandatory items

- [ ] Names the active action and resumes at the first unresolved gate instead of replaying the whole workflow.
- [ ] Searches for governing documents before concluding none exist; inspecting only the expected file does not count as a search.
- [ ] Records which modules were read and which were skipped with a reason.
- [ ] Surfaces a source conflict and picks a winner with a stated reason rather than averaging the sources.
- [ ] Enforces no rule it cannot cite to a document or an observed defect; never hardens an inferred rule into a test, lint, or locked token.
- [ ] Preserves source wording, section order, links, counts, and states when migrating an existing surface; every omission is explicitly approved.
- [ ] Keeps copy, controls, semantics, and the next action in accessible DOM.

## Case 1 — Carrier medium

- [ ] Runs the medium scan for the decisive screen **after** the content model and carrier are fixed, and **before** composing.
- [ ] Shortlists at least one non-DOM candidate when time, depth, continuity, procedure, many marks, or direct manipulation is material.
- [ ] Records the selection contract: selected medium, observable communication gain, closest rejected alternative and why it loses.
- [ ] Rejects an advanced medium for cost/meaning reasons rather than defaulting to DOM by familiarity. A DOM/CSS outcome passes only when the scan preceded it.
- [ ] Reserves carrier geometry before load; a failure or unsupported device leaves the claim and next action intact.
- [ ] Provides static, reduced-motion, offscreen-pause, and failure states with the carrier, not afterwards.
- [ ] Authors a reassembly at the pressured width instead of shrinking the desktop scene.

**Automatic fail:** a medium verdict recorded before the module was opened, or an advanced renderer that owns copy, controls, or the only meaningful state.

## Case 2 — Governing rule discovery

- [ ] Runs an actual search across the project for decision records, reports, and rule documents, not only token or component files.
- [ ] Applies the governing role table as written, including its forbidden ranges.
- [ ] Separates language blocks rather than alternating faces inside one sentence.
- [ ] Reports any rule it could not source and marks it provisional instead of enforcing it.
- [ ] Any test it writes to protect a design decision cites the document or defect it came from.

**Automatic fail:** an invented rule enforced as a passing test, or a governing decision record that existed in the project and was never opened.

## Release items

- [ ] Runs the visual-completion gate before the mechanical pass, and reports them separately.
- [ ] Verifies the canonical widths plus one pixel each side of every changed breakpoint; reports the quality-valley check, not only overflow.
- [ ] Records capture provenance for any spatial finding; unknown provenance keeps the finding provisional.
