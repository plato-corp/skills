# 파형 맥락 사물 워크플로 (2026-10-21 승인 생성 방향)

사용자가 좋다고 승인한 **생성 방향**입니다. 이것은 특정 사물 네 개를 정식 사물 목록으로 채택하거나, 이 파형 처리를 전역 기본값으로 삼으라는 뜻이 **아닙니다**. 전체 통째 채택(blanket canonical adoption)이 아닌, 아래의 선택·파이프라인·검토 방식을 따르라는 것입니다. 파형 처리의 승인 상태는 여전히 IN REVIEW이며, 정식 밀도·속도·색 토큰은 권한 있는 가이드/온톨로지에서 해결합니다.

패키지된 리뷰 참조: [waveform-context-20261021/](waveform-context-20261021/) — 네이티브 렌더러 사본, 입력 필드, 자체 포함 애니메이션 `review.html`, 2×2 콘택트 시트, 480px 소스 썸네일, 출처·해시 `manifest.json`.

## 1. 사물 선택 — 의미로 고른다

파형으로 바꿀 소스 사물은 **Tiro와 의미적으로 연결된 대화·기록·정리 맥락 사물**에서 고릅니다. 형태만 보고(visual shape only) 고르지 않습니다.

- 선호 검토 예시(이번에 승인된 방향): **두 의자, 겹친 메모지, 수첩과 펜, 테이블 마이크**. 각각 대화/정리/기록 맥락을 담습니다.
- 반례: 조개(shell)·강돌(stone)·코일(coil)처럼 **시각적 실루엣만** 보고 고른 사물. 이들은 이 라우트에서 폐기(superseded)된 실험 후보입니다.
- 사물은 [소스 오브젝트 방향](../SKILL.md#selecting-the-image-before-waveform-conversion)의 3D·명암 대비·식별 가능한 실루엣 기준을 그대로 만족해야 합니다. 의미 연결과 형태 식별성은 둘 다 필요합니다.

## 2. 소스 생성 — imagegen은 소스 사진에만

- imagegen은 **3D 소스 사진을 만들 때만** 씁니다. 넓은 명암 대비, 입체감, 식별 가능한 실루엣을 가진 실물 사진/렌더를 생성합니다. 글자·UI·플랫 로고 없음, 단색 배경.
- 이미지 모델에게 **파형을 그리라고 요구하지 않습니다.** 가짜 손그림 파형 금지.
- 소스는 그레이스케일로 샘플링되어 네이티브 가로 파형 입력 필드가 됩니다.

## 3. 파형 렌더링 — 원본 네이티브 그대로

파형은 **원본 HTML 파형 렌더링을 그대로** 씁니다. Python 근사 렌더러, blur, stretch, gamma 재작성으로 파형 모양을 만들지 않습니다.

- 네이티브 렌더러 바이트 보존: `stepped-wave.js`의 SHA256은
  `c3931500251c72857fb51d05000c97591787fe91099d12890b735a29dafec529`
  와 일치해야 합니다. 함께 쓰는 `wave-horizontal.js`, `wave-density.js`도 패키지 사본을 그대로 씁니다.
- 네이티브 설정(이번 리뷰 스냅샷 기준): **stepped-medium · 60 캐리어 · 가로축 · 연속 느린 흐름 · 종이-잉크(paper-ink) 마스크**.
- 색은 이 리뷰의 **다크 프리셋**입니다: fg `#CAC0B6`, opacity `0.299`, bg `#191614`. 이것은 소스 스냅샷에서 가져온 **리뷰 프리셋이며 채택된 전역 토큰이 아닙니다.** 정식 색은 권한 있는 가이드/온톨로지에서 해결합니다.

### 재사용할 소스 프롬프트

공통: 정사각형 그레이스케일 3D 실물 렌더. 검은 단색 배경, 상단 왼쪽의 넓은 광원, 밝은 면과 깊은 음영, 미세 장식보다 큰 명암 덩어리. 전체 사물이 보이고 가장자리 약 14% 여백. 글자·로고·UI·파형 없음. 아래 사물 설명을 붙입니다. 이 여백은 소스 생성용 출발값이며 최종 크롭 규칙이 아닙니다.

| 사물 | 추가 설명 |
| --- | --- |
| 두 의자 | 서로 약간 마주 보는 회의용 의자 정확히 두 개. 하나는 조금 뒤에 배치. 3/4 위 시점, 등받이·좌판·다리와 두 의자 사이 빈 공간을 보존. 테이블 없음. |
| 겹친 메모지 | 두꺼운 정사각 메모 패드 세 개가 대각선으로 어긋나게 겹침. 페이지 단면과 살짝 말린 빈 윗장이 보이는 3/4 위 시점. |
| 수첩과 펜 | 중앙 접힘선과 두꺼운 페이지 단면이 보이는 작은 펼친 수첩. 오른쪽 아래 페이지 위 만년필 하나를 대각선으로 배치. 펜과 페이지 사이 명암 분리를 확보. |
| 테이블 마이크 | 넓은 원형 받침, 짧고 기울어진 지지대, 둥근 마이크 헤드가 연결된 탁상용 마이크 하나. 3/4 시점으로 세 부분이 구분되게. |

### 새 사물 생성에 사용할 로컬 빌드

현재 재생 가능한 렌더러·필드·비교 HTML은 스킬 안에 묶여 있습니다. **새 소스의 필드 베이크와 PNG 내보내기 도구는 로컬 작업 폴더에만 있습니다.** 리뷰 HTML만으로 새 사물이 자동 생성된다고 설명하지 않습니다.

필드 베이크 도구는 이 공개 리뷰 패키지에 포함되지 않습니다. 원본 제작 환경에서 해당 빌드 도구를 확보한 경우, 원본 작업을 덮어쓰지 말고 새 작업 폴더에 복사한 후 다음 입력만 바꿉니다. 아래 파일명은 그 제작 도구의 인터페이스를 설명하며, 이 패키지에 존재한다고 가정하지 않습니다.

1. `adapter/sample_blackground.py`의 `ORDER`에 새 PNG·슬러그를 등록하고 소스를 그리드로 샘플링합니다. Python은 입력 샘플링용이며 파형 그림을 대신 그리는 용도가 아닙니다.
2. `build-fields.cjs`의 `MAPPING`에 네이티브 클래스와 밀도 인덱스를 등록하고 `node build-fields.cjs <grids-dir> <fields-js> <meta-json>`으로 입력 필드를 만듭니다. 원본 `fractionAt`·밀도 보정·필드 계약을 유지합니다.
3. `render-harness.html`에서 새 필드를 로드하고 원본 `HorizontalWave([],60,1,key)` → `SteppedWave.render`로 렌더링합니다. `export.cjs`의 사물 목록·파일 경로·설치된 Playwright 위치를 환경에 맞춥니다. 비교용 정지 시점은 이번 세트와 같은 `7.3`입니다.
4. 정사각 출력이 요청되면 390×380 원본 비율을 유지합니다. 1080×1052 렌더에 위아래 14px 배경을 더해 1080×1080으로 만들고 파형 자체를 늘리지 않습니다. SVG에도 상속 색·opacity가 보존되는지 확인합니다.

다른 환경에 로컬 빌드가 없으면 생성 전에 이 의존성을 알리고 빌드 도구를 확보합니다. 임의의 근사 파형으로 대체하거나 기존 네 사물의 필드를 새 사물 결과처럼 재사용하지 않습니다.

## 4. 새 입력 데이터는 문서화하되 "원래 있었다"고 주장하지 않는다

사물별 **그리드·배치(placement)·네이티브 클래스 매핑**은 이 사물 세트를 위해 새로 준비한 입력 DATA입니다. 허용되지만, 원본 소스에 원래 존재했던 것처럼 주장하지 않습니다. `manifest.json`에 매핑과 새 입력을 기록합니다.

- 이번 세트 매핑: 두 의자→meeting(0), 겹친 메모지→conversation(1), 수첩과 펜→notebook(3), 테이블 마이크→globe(5).
- 네이티브 스타일·알고리즘은 바꾸지 않습니다. 바뀐 것은 입력 필드/매핑/배치/레이아웃뿐입니다.

## 5. 출력과 리뷰

- **수량은 명명**합니다(예: 선호 예시 4종). 통째 채택이 아니라 요청·확립된 범위에서만 확장합니다.
- 갤러리 리뷰는 **풀사이즈와 320px** 둘 다로 봅니다. 사물이 **읽히되 파형에 녹아들어야** 하며, 라벨만으로 식별성을 구제할 수 없습니다.
- 콘택트 시트(비교 시트)로 4종을 한 번에 비교합니다. 소스 비교(느린 모션) HTML은 **선택**입니다.
- `notebook-pen`은 식별성이 약하다는 **개선 메모**가 있습니다 — 보편 PASS가 아닙니다. 식별 실패 또는 불확실한 경우 fix/unverified로 기록하고 최종 승인 전에 배치·크롭·소스를 수정합니다.
- 1080 정사각 등 추가 포맷은 **요청되거나 확립된 경우에만** 상속합니다. 기본 강제가 아닙니다.
- 인테이크 형식은 기존 SKILL.md의 인테이크를 그대로 씁니다. 원시 그래픽(raw graphics)에는 제품 포함/브랜드 전용 **페어(productpair)를 만들지 않습니다.** 제품 UI 증거가 필요할 때의 최신 프로덕션 캡처 규칙은 그대로 유지됩니다.

## 6. 다른 스타일 요청은 강제하지 않는다

사용자가 **다른 스타일**을 명시적으로 요청하면 이 파형 방향을 강제하지 않습니다. 이 워크플로는 맥락 사물 파형을 요청했을 때의 생성 방향일 뿐이며, 모든 요청의 기본값이 아닙니다.
