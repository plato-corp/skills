## Default waveform background

Finished marketing content uses a waveform background by default in all three themes, including photo-led and text-led layouts. An explicit request for no waveform, a plain background, faithful source reproduction or an incompatible different treatment overrides that default. This composition preference does not claim formal adoption of every review preset, ontology migration or production UI deployment. Thin/thick profiles remain comparison candidates.

Use the preserved original HTML renderer and existing fields in [waveform-context-workflow.md](waveform-context-workflow.md); do not substitute generated wave drawings or arbitrary stripes. Existing graphics may be reused; a new object is not mandatory for each composition. New objects must follow the source and recognizability requirements. Missing renderer/reference leaves the layer pending and must be disclosed.

Keep waveform subordinate to title, logo and evidence. It is a separate background layer, never painted into a product screenshot or over a defining photographic gesture. Distribute it across the canvas rather than concentrating its mass behind the headline.

**To extend background coverage, preserve the chosen line thickness, carrier pitch and native profile. Enlarge the viewport or continue/repeat the original carrier field at its exact pitch; do not enlarge the entire waveform artwork to fill a taller canvas.** Reposition waveform detail separately from the continuous field. Record any carrier continuation/placement as composition work, not an unchanged source export; keep native renderer files byte-identical. Opacity may be adjusted per theme for readability, without changing token identity. Inspect top/bottom transitions, seams and photo margins at full size and320px. Motion-capable delivery retains slow flow and reduced-motion behavior; PNG is a deterministic still.

## Logo and typography

A separate logo is optional unless required by the brief. Omit it when publishing context already identifies Tiro or it weakens the composition; do not add replacement ornament. If used, preserve original geometry and use authorized ink/variant.

Align logo and title as one group: left-aligned title → same left rail; centered title → same center axis; right-aligned title → same right rail. Check visible artwork rather than only text-box bounds. An off-axis logo needs a reason such as faithful source reproduction or an explicit hero-logo role. Never use an arbitrary corner or fill empty space by habit. Check clear space, title distance, contrast and visual isolation; compare with/without logo if its role is unclear.

Use the shared current title contract, not a separate marketing baseline. The user's current Korean default is real variable **Hahmlet515**, adjustable only within **500–600**; no weight above600, faux bold, stroke/duplicate tricks or family substitution to bypass the limit. Stronger emphasis can use size, contrast and placement. Standalone English display uses actual **wdth120** and **line-height1.1**; mixed Latin retains its distinct calibrated role. Preserve body/UI/wordmark roles. Verify actual loaded glyph fonts and axes, not CSS declarations alone.

No decorative eyebrow is required. Preserve meaning and supplied wording. Run an available `im-not-ai`/`humanize-korean` skill on newly authored Korean copy; record actual execution. Previously reviewed unchanged copy may be reused with provenance. If unavailable, disclose it rather than claiming a pass.

## Review and delivery

Choose an appropriate layout family; source geometry may inform a new ratio, but historical colors and logo anchors do not override the current brief. Preserve geometry only when explicitly reproducing a source; record scoped changes. A deliberate photo/text split is valid. Warm photos need a meaningful connection through scene/copy/evidence, not a compulsory nib or logo prop.

Review each theme as an actual full image and320px preview: title/logo axis, semantic line breaks, real type, text bounds, meaningful photo/object crop, waveform scale/pitch/distribution and theme contrast. Structural checks do not certify artistic approval. Deliver individual images plus editable source, show the images in chat, and retain the same final artwork in the authorized Figma destination when available. State when Figma is raster-only and retain editable typesetting separately. Do not mistake archival, written rules or a single same-agent sample for user approval or demonstrated repeatability.
