# Ground and shape

Read this module for `shape` and `integrate`, when establishing a page job, or when content migration is a named risk. For bounded craft, polish, audit, or release, reuse the locked page job, message, and migration inventory unless their inputs changed.

## 1. Ground the page

Classify the visitor job before applying landing conventions:

| Job | Visitor success | Typical surface |
|---|---|---|
| Persuade | Believes the promise and acts | Product, promotion |
| Decide | Uses inputs to judge a recommendation and cost | ROI, pricing, plan selector |
| Read | Understands or verifies | Security, Q&A, policy, article |
| Route | Finds the right destination | Docs or resource gateway |
| Operate | Completes a recurring task | Use `ui-design` |

Use a job-specific default argument unless verified entry intent requires another order:

- `Persuade`: promise → mechanism → proof → objection → action
- `Decide`: promise → input → answer → rationale → objection → action
- `Read`: question → answer → evidence → boundary → next reference
- `Route`: orientation → choices → distinctions → destination

For `Decide`, the primary interactive surface and its answer appear before detailed rationale. Preserve an explicit `input → result → save` route. Plan details, calculation assumptions, quote documents, and FAQ are supporting information and cannot precede the answer or share its visual weight.

Inspect only the active sources needed for the page: workspace rules, current route and rendered page, the two closest sibling public pages, shared navigation/footer, current design-system sources, verified product facts, CTA destination, and supplied references. Treat legacy work and old experiments as evidence, not approval. Expose source conflicts and keep mutable claims centralized as `confirmed`, `conflict`, `provisional`, or `omit`.

When redesigning or migrating an existing public surface, establish content and interaction parity before changing its architecture. Inventory every source route and tab; every heading, paragraph, list item, date, count, link, document, and status; and every public, restricted, locked, request, expanded, or selected state. Preserve source wording exactly unless copy changes are explicitly in scope. A representative subset, shortened landing summary, or merged one-scroll page is not parity.

Choose `one page`, `in-page tabs`, or `separate routes` from information density and visitor workflow, not from a preference for visual simplicity. Dense review, policy, documentation, or evidence surfaces should retain stable destinations, deep links, comparison context, and access-request states. A redesign fails if it removes content, hides meaningful distinctions, or turns a reviewer workspace into a promotional page. Centralize migrated content where practical and add deterministic checks for route coverage, item counts, access-state counts, and high-risk exact strings.

Establish the site-family contract before solving the page. Compare sibling Heroes at the same CSS viewport and browser zoom. Lock the shared desktop container, default alignment, H1 ceiling, eyebrow and lede stack, action hierarchy, carrier docking behavior, and mobile rule. For the current Tiro detail-page family, Pricing, Security, and Download share a left-aligned desktop Hero unless a maintained family source establishes a different rule for all three. Download may center on mobile as an explicit utility exception; its current centered desktop implementation is evidence to review, not a governing exception. Page-specific evidence changes the carrier, not the family grammar by default.

Do not invent claims, dates, metrics, certifications, fonts, tokens, colors, radii, or breakpoints. Diagnosis and research are read-only. Change project files only when the user asks to implement or modify them.

## 2. Lock message and copy

Write the minimum copy spine before layout:

```text
Purpose: one intended visitor change
Page thesis: one sentence every section must advance
Hero claim:
Proof line:
Primary CTA:
Argument sequence / next-section bridges:
Intended belief and 2–3 after-feelings / anti-feelings:
Unknowns:
```

Copy must pass the stranger test, select one reader, front-load the point, keep one idea per unit, and place proof beside the claim it earns. Cut empty hedges and AI-default language. Preserve approved or legacy copy exactly when rewrite permission was not given. If the angle is unresolved, compare 2–3 materially different copy spines without changing the visual system at the same time.

Run a compression pass on every decision route. Give each fact one visible owner, then remove or collapse any heading, stage marker, field number, status counter, helper line, or body sentence that only restates it. Keep a progress indicator only when the visitor must orient across a non-obvious multi-step process; visible input, answer, and save regions do not need a second diagram of themselves. Keep constraints and remedial help quiet until they are needed before an action or after an error. Use the removal test: if deleting a fragment changes neither interpretation, decision, nor action, it does not stay visible.

Split every compound claim into clauses before designing its section. Record the subject, allowed input or action, boundary or transformation, prohibited state, and proof. A clause that has no verified proof must be qualified or removed; a clause that matters to the one-second message must have a visible counterpart in the carrier.

The page thesis is an internal decision standard, not necessarily the Hero sentence. Assign each section one argument act such as `promise`, `explain`, `bound`, `prove`, `qualify`, `resolve`, or `act`. The section must change what the visitor knows or believes and make the next act necessary. If removing it leaves the argument unchanged, cut or merge it.

Name the intended after-feeling and its opposite before art direction. Translate `safe`, `mature`, or `trustworthy` into observable evidence and perceptual consequences; do not style adjectives directly. Bright is not inherently naive and dark is not inherently professional. Trust can come from precise hierarchy, controlled contrast, credible people or environments, legible product states, explicit boundaries, independent proof, and motion that demonstrates a real control.
