# Decisive scene, integration, and responsive composition

Read the decisive-scene portion only when a material visual choice remains. Read integration rules when assembling or structurally changing sections. For a bounded responsive correction, enter at the affected width contract and adjacent composition; reuse locked page-level decisions.

## 5. Compare only the decisive scene

Produce one direction when the answer is clear or 2–3 directions when one material choice remains. Hold copy, facts, CTA, component language, and viewports constant. Each candidate contains only the complete Hero and its transition into one decisive next section, shown at intended desktop and mobile browser sizes with real Korean copy.

When the primary carrier is unresolved, vary the carrier and its necessary color climate while holding the message and base composition constant. Do not vary the whole page or disguise one carrier as three stylistic treatments.

When the carrier is locked but the rendering medium is unresolved, compare the smallest actual-size decisive scene in 2–3 plausible media while holding its content model, evidence, copy, composition bounds, and fallback meaning constant. Compare the observable communication gain and the runtime envelope, not novelty. Show only the winner when the evidence is clear.

When title alignment is the unresolved material choice, compare only the relevant left, center, right, or asymmetric treatments on the same actual-size scene. Keep copy, evidence, type scale, color, and carrier fixed. Do not build several full pages or alternate alignments merely to create variety.

Use the active approved type scale. Without one, cap detail-page H1 at `38px` desktop and `32px` mobile, and H2 at `32px` desktop and `28px` mobile. Fluid type must remain within the same ceiling. Check Korean wrapping at 390px and 360px. Build drama with evidence, composition, and pacing rather than oversized type.

Stop for approval unless Autonomous mode is active. In Autonomous mode, record the direction lock and why it was selected before expanding it.

## 6. Expand one master, then integrate it

Maintain one complete master. Keep local A/B/C options only for unresolved sections and freeze approved decisions. Do not create several global concepts that silently vary the same sections again.

Arrange the page by its visitor-job argument. `Decide` defaults to `promise → input → answer → rationale → objection → action`; other landing pages may use `promise → mechanism → proof → objection → action`. Before local styling, give every section an integration ledger:

```text
Role / intensity:
Visitor question / contribution to the page thesis:
Viewport attention: dominant / no more than two supporting items / next cue / de-emphasized:
Evidence / feeling before → after:
Content model / entities / relationships / protected or changed state / semantic invariant:
Diagram grammar when applicable / label-hidden inference / prior-carrier comparison:
Target height / width behavior:
Action width contract: natural width / maximum width / collapse trigger / allowed line count / reassembly:
Macro silhouette:
Spatial frame: bounds owner / coordinate frame / occupied anchors / intentional empty regions / reading path / breakpoint reassembly
Primary carrier:
Asset source / production method / crop or fallback:
Rendering medium / communication gain / closest rejected alternative:
Runtime envelope / dependency boundary / loading, failure, unsupported, static, and reduced-motion states:
Color climate / area distribution / anti-drift check:
Entry and exit transition / why the next section follows:
Primary answer / supporting information / disclosure state:
Desktop order / mobile order:
Title container / alignment / max width / intended phrase breaks:
Repeated pattern family / shared geometry or justified difference:
Surface boundary mechanism and line topology: each line's start element / end element / readable relationship
Closing strategy when applicable: continuation / handoff / rupture
```

Repetition is allowed when equivalent content should be recognized as a family. When two sections repeat a macro, bind them to one geometry contract: outer container, grid template, title axis and measure, content axis, gap, divider inset, and breakpoint transition. Change an internal measure only when evidence density requires it; do not make the outer skeleton almost match. Three or more consecutive repeats require a rhythm review, not automatic variation.

Give every pair of adjacent sections a handoff contract: outgoing carrier edge, incoming carrier edge, shared or intentionally changed outer width, overlap or gap, and the exact scroll frame where both can be seen. Unowned whitespace between mismatched max-width axes fails even when each section looks complete alone. A width change is valid only when the transition itself explains the expansion or contraction.

After assembly, run a root art-direction pass over title scale, color distribution, spacing, hairlines, corner frequency, product density, section heights, and adjacent silhouettes. Quiet, shorten, restage, remove, or merge a locally good section when the page rhythm requires it.

For `Decide`, verify that the input produces one visually dominant recommendation or cost answer before explanation begins. Keep plan comparison, assumptions, quote detail, and FAQ behind progressive disclosure unless one of them is required to interpret the answer itself.

Define one home axis for informational section titles. The title-only map must still make that axis obvious; if exceptions equal or outnumber titles on the home axis, the page has no dominant axis. Use left alignment for sequential reading and longer explanation, center alignment for a singular proposition or formal pause, right alignment for a real counterpoint or opposing carrier mass, and asymmetry only when the title participates in the content relationship. An exception moves the section composition, not the heading alone. Normalize it when returning to the home axis loses no meaning. Exclude the closing CTA from this count and resolve it through the closing strategy.

A title may leave the normal reading width only when the section also owns a named stage width, an independent composition or surface, and a content-specific mechanism that justifies the exception. Never create distinction with an arbitrary offset alone. Give each primary title a semantic max width and intentional phrase boundaries, then inspect the result at every target breakpoint. Desktop alignment may return to left on mobile when centered or right-aligned Korean harms reading. Prefer phrase spans or breakpoint-scoped breaks when they preserve meaning; do not force unnatural syllable breaks or let manual breaks damage intermediate widths.

Classify the final CTA before styling it. `Continuation` stays in the current field and emphasizes only the action. `Handoff` carries the accumulated evidence into another destination without pretending it is a new campaign. `Rupture` creates a deliberate new field only when the narrative truly changes phase. Name its anchor: prior evidence, a bounded destination field, a continuing carrier, or the footer handoff. Run the relocation test: if the CTA can move to any page or any vertical position without losing meaning, it is floating and fails. A new color, gradient, photo, or rounded surface must explain the narrative change or destination; it cannot exist only to make the close feel substantial. A full-width color strip is never the default closing treatment.

Whenever a section contains a gate, route, containment, hierarchy, branch, sequence, or transformation, map that relationship before drawing its geometry. For a high-stakes nonstandard section, privately compare at least three macro silhouettes, choose the one whose spatial logic best explains the relationship, and test it with labels removed and with the brand swapped. Show only the strongest decisive scene unless a real decision remains. A tasteful but merely intermediate arrangement is not a shippable fallback.

Every user-stoppable scroll or sticky state must be a valid composition. Do not use speed, blur, or automatic completion to hide an unattractive intermediate frame. Use one major explanatory motion per viewport, with at most one supporting motion. Mobile is an independent editorial and intensity pass; replace fragile sticky behavior with stacked or user-controlled states when needed.

Do not disable a meaning-bearing desktop transition at a broad tablet breakpoint as a convenience. At the first pressured width, either author a tablet version that preserves the state change or name and implement an equivalent static or user-controlled carrier. Reserve the phone fallback for the breakpoint where the transition can no longer remain legible or operable, and verify one pixel on each side of that cutoff.

Treat responsive work as component pressure management, not a list of device names. For every heading, paragraph, action group, compound control, comparison, and complex carrier, declare:

```text
Natural width:
Maximum useful width:
Collapse trigger: the first width where hierarchy, padding, or meaning degrades
Allowed line count: one line, deliberate two lines, or free flow — and why
Reassembly: what moves, stacks, simplifies, or leaves the control
```

Start short actions at intrinsic or content-fit width and cap them explicitly. Full-width is valid only when the action has block semantics, aligns a form or comparison column, or belongs to a deliberately bounded local action stack. It is not a mobile default. Test whether a short label fits on one line before wrapping it, but do not convert this into a one-line-only rule: a deliberate two-line label or copy block is preferable when it preserves meaning and a better maximum width. Browser-created accidental wraps fail.

When a control wraps or loses padding, first test whether its parent layout should reflow earlier. Do not solve five compressed cards by shrinking type, squeezing padding, or adding `white-space: nowrap`. Choose breakpoints from measured content pressure; device labels are only test checkpoints. Tablet and mobile may share hierarchy, but each needs an authored composition rather than a proportionally shrunken desktop scene.
