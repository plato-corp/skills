# Mixed Operate surface routing

Use this contract when a recurring product task is explicitly assigned to both `ui-design` and `landing-design`. `ui-design` leads the surface. Landing design owns only a named, bounded contribution that cannot compete with the task.

## Collaboration receipt before craft

Record all fields before implementation:

```text
Operate surface: <screen and recurring task>
Primary outcome: <one user job>
Preserved task content and states: <actions, inputs, consent, errors, recovery, loading, success>
UI contribution: <hierarchy or behavior decision changed>
Landing contribution: <bounded carrier, brand rail, or public handoff decision changed>
References inspected: <product sources and 2–4 real category references for every new visual direction>
Decision changed by each reference: <visible extraction → Tiro translation>
Rejected additions: <marketing copy, carrier, decoration, or behavior that would compete with the task>
Attention ceiling: <measurable maximum area or pixel extent; permitted copy/contrast; breakpoint removal criterion>
Evidence paths: <sources, captures, tests>
```

Typography, color, spacing, and image replacement are implementation outputs, not evidence that a skill ran. Do not claim a skill was applied unless its required sources were inspected and at least one named decision changed inside its allowed scope.

## Required sequence

For the UI-owned task, follow the `ui-design` contract from grounding and primary outcome through state, responsive, and release verification. For the bounded landing contribution, follow `study → shape → direction → craft → release`; reuse locked evidence where valid, but do not jump directly to craft because the contribution appears decorative.

At `study`, inspect 2–4 real category references for every new visual direction; skip only a bounded conformance fix where no direction changes. At `shape`, state why the landing contribution is necessary and set a measurable attention ceiling: maximum area ratio or pixel extent, permitted copy and contrast, plus the breakpoint condition that removes it. At `direction`, select the decisive composition and name what the references changed. At `craft`, preserve the UI task inventory and state model. At `release`, verify that the task remains identifiable within one second and that the landing contribution cannot be mistaken for the primary action. Capture the removal breakpoint at `-1px / +1px` and record the measured area or extent on the wider side.

Craft inside the authorized output: use an isolated prototype for exploration or redesign by default, and change production only when the user explicitly asks to implement there. Autonomous mode removes intermediate approval pauses; it does not expand the production permission boundary.

## Stop conditions

- Remove the landing contribution when it has no evidence-bearing or brand-bearing job.
- Reject promotional copy on login, signup, or another Operate surface when it delays the task or repeats context the user already has.
- Do not claim both skills were applied when one skill supplied no inspected source, bounded decision, or release evidence.
- Do not ship a mixed result that is merely a beautified version of the current screen.
